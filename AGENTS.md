Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code.

## Styling

All UI styling uses Unistyles v3 with the token theme in `src/theme/`.
Before writing or changing any styling, read the full standards:

@docs/styling-standards.md

The essentials:

- Import `StyleSheet` from `react-native-unistyles`, never from `react-native`.
- Colors come only from `theme.colors.*` (semantic roles). Never read `palette` in components.
- Text: spread a `theme.typography.*` variant and set `color` separately. Never use `fontWeight`.
- Spacing, radii and shadows use `theme.spacing.*`, `theme.radii.*`, `theme.elevation.*`.
- No hard-coded hex, font names or magic numbers, and no inline style objects.
- Keep UI code under `src/`. Check every screen in both light and dark.
- Adding a font or native module needs a native rebuild. Plan it and batch such changes.

## Workflow rules

- Commit messages must follow Conventional Commits (`feat: ...`, `fix(scope): ...`).
  Husky + commitlint reject anything else.
- Never name a package.json script the same as a binary in `node_modules/.bin`
  (expo-doctor fails on it). Use a suffix, e.g. `lint:staged`.
- `android/` and `ios/` are generated by CNG and gitignored. Never edit them. Change
  `app.json` or config plugins instead.
- Keep `plugins/withDebugNetworkSecurityConfig.js` registered in `app.json`. It lets
  debug builds trust the corporate proxy CA on the Android emulator.
